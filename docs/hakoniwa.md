# 箱庭計画 (Hakoniwa)

Rustbound の製品着地定義。バニラ同等の無限生成・完全 AI は目指さない。
**固定サイズの箱庭で、軽量に Minecraft Java 1.20.1 クライアントと遊べること**を完成条件とする。

## 製品一文

> 現世／ネザー／エンド（エンドシティ含む）の固定マップをサイズ3種まで同梱し、歩ける・壊せる・次元を移れる・Mobは簡易・液体は静的から。生成アルゴリズムは作らない。バイナリは極限まで小さく保つ。

## やること / やらないこと

| やる | やらない |
|------|----------|
| 固定マップデータセット（サイズ tiny / small / medium） | 無限・手続き的バニラ地形生成 |
| ワールド境界（マップ外に出ない） | Forge mod 互換 |
| ブロック衝突（歩行の前提） | 全 Mob 完全 AI |
| 次元切り替え（ポータル or 明示テレポート） | レッドストーン完全一致 |
| Mob：装飾 → 数種の簡易敵対 | 統合版プロトコル |
| 液体：静的 → 必要なら流動 | 公式成果物の取り込み |
| 配布バイナリの小型化（LTO / size opt） | |

## サイズプリセット

チャンク半径はスポーン中心の正方形（一辺 = `2 * radius + 1` チャンク）。

| 名前 | チャンク半径 | 一辺チャンク | ブロック幅（約） |
|------|-------------|-------------|------------------|
| `tiny` | 4 | 9×9 | 144 |
| `small` | 8 | 17×17 | 272 |
| `medium` | 16 | 33×33 | 528 |

各サイズについて、将来は **overworld / nether / end** のデータを用意する。  
Phase H2 では overworld の組み込みマップパック（装飾付き箱庭）＋ `.rbpk` 読み込み。

## マップパック

- 形式: `{level}/packs/{tiny|small|medium}.rbpk`（無い場合は組み込み）
- マジック `RBPK`、装飾ブロックの疎なリスト（掘る/置くの `blocks.bin` とは別レイヤ）
- 組み込み: 芝生広場・境界壁・サイズ別ランドマーク（ダイヤ／エメラルド／石炭ブロック）

## 小型化

| ビルド | 目安 |
|--------|------|
| `cargo build -p rustbound-server --release` | ~1 MB 前後 |
| `cargo build -p rustbound-server --profile dist` | ~0.6 MB 前後（strip + LTO + `opt-level=z`） |

サーバ実行ファイルは既に小さい。配布物の主サイズは **同梱マップ**になる。  
マップは「入れた分だけ」：未同梱次元は無効。

## 設定

`server.properties`:

```properties
hakoniwa-size=tiny
```

`tiny` / `small` / `medium`。省略時は `tiny`。

## クリーンルーム

マップは自前生成または利用者が手元のバニラ等で作ったワールドを **読む**前提。  
Minecraft / Forge jar・逆コンパイル・mappings はリポジトリに入れない（[AGENTS.md](../AGENTS.md)）。
